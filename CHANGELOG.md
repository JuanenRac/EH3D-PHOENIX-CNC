# Changelog

All notable changes to this project are documented here.

## [Unreleased]

## [0.2.7] - The position follows the machine and an option stops the spindle on pause (not tried on a machine)

- **Third-party notices in every package (`docs/THIRD_PARTY_NOTICES`):** the packages of the releases now carry the copyright notices and licence texts of the Rust crates and of the data the program is built with, and the CI fails when a new dependency or licence is not in the file.

- **The CI compiles the build with the serial port** (`--features serial`), which nothing built before.
- **The position follows the machine while a line waits for its `ok`:** the window asks for a status report out of turn and shows the report that comes back, instead of keeping the last status until the line ends.
- **An option to stop the spindle on a pause, off by default (not tried on a machine):** `grbl_spindle_stop_on_pause` in Settings and in the settings file makes a pause of a GRBL or grblHAL controller also send the safety door byte (`0x84`), which stops the spindle and the coolant until the program goes on. A door state that is not confirmed is said in the log, a Start gives the resume again while the machine stays in its door state, and it takes effect the next time the program is opened. Tried against the simulated GRBL only.
- **The workflows take EH3D-COMMON v0.3.9.**

## [0.2.6] - The emergency stop reaches the job of the server, safer restarts and imports (not tried on a machine)

- **The log of the session speaks the eight languages:** the answers to the jog, the stop, the travel, the probe, the tool setter and the height map, the end of a program and the lines the program stops at were written in English whatever the language of the window. They follow it now (the words a controller sends stay as it sends them), and the exported log still marks the errors in each language.
- **Why a program is not resumed is told in your language:** the reasons (relative distances, a cycle or a cutter compensation left on, a shifted zero, a move in machine coordinates, an arc not said again, a feed mode, a tool length from the table, an offset set again) were English only.
- **The log of the link to the server and of the queue is in the eight languages:** sending and following a job, its state, the link, the refusals of this program to send a job again and every line of the queue.
- **The head of the path view fits a narrow panel:** in German the hint was cut, and the size of the table at the foot with it, because one long row made the panel wider than its place. The rows now go on below.
- **Probe and tool setter cycles run in millimetres whatever units the program left:** after an inch program the controller stayed in `G20`, so a probe of 10 mm went down 10 inches and the moves of the grid and of the setter went 25.4 times too far. Each cycle now says `G21` and gives `G20` back, also after a touch that fails. Tried against stand-ins only.
- **Zero and touch-off write the work system in use:** with `G55` to `G59` selected, the probe and the zero buttons of a GRBL controller wrote `G54`, so the program cut at the old zero. They now write the one in use (`P0`).
- **The height map refuses what it cannot correct:** canned cycles, probes, threads and splines were rewritten into broken lines, and a feed by inverse time, a second work system, an offset of X or Y, a rotary axis on a cut that must be split and a line that cannot be read were let through. Each is now refused with its line, in the eight languages.
- **The height map invents no position:** a cut before the program had said where the tool is, or after `G28`, `G30` or a change of the tool length, was written from `X0 Y0 Z0`, a move that nobody asked for. It is now refused. A rapid line keeps its feed.
- **A pause or an end on a corrected line stays at its end:** an `M0` or `M30` on a cut that the height map split went with its first piece, so the program paused or ended part of the way.
- **Mirroring a program with arcs adds nothing to the other lines:** after an arc, a comment, a blank line, `M5` or a speed got `G3` in front of it, which the controller refuses with the spindle turning. `$` lines and messages are left alone.
- **A mirrored shape keeps the tool on the right side:** `G41` and `G42` (and `G41.1`, `G42.1`) are now exchanged when a mirror turns the shape over; before, the part was cut a tool diameter too small or too big.
- **A transformation refuses a line it cannot read:** a word written as an expression or a variable stayed where it was while everything around it moved.
- **A macro that starts the spindle or changes the tool asks first:** with `macros_confirm = no`, a macro marked `confirm = no` with `M3`, `M4`, `M6`, the coolant or a homing ran at the press of its button.
- **The point to go on from is kept until the machine stands still:** the file was taken away when the controller had taken the last line, while it was still cutting the lines in its buffer.
- **A program is not resumed over a zero shifted by hand:** a `G92` typed by hand (or the zero button on Marlin and Klipper) is lost when the controller resets, and nothing noticed. The recovery file keeps it in mind and says so instead of resuming.
- **DXF drawings are measured and placed as they say, or refused:** mils, microns, decimetres and the other units were read as millimetres, shapes seen from behind were cut mirrored the wrong way, and the frame of the paper sheet was cut with the part.
- **A DXF shape that cannot be read refuses the file:** a missing or broken number left the shape out, or drew it from the numbers that remained.
- **The transformations of SVG drawings are applied:** moved, scaled, turned and skewed groups and shapes were cut where they were first drawn, with only a note.
- **What an SVG drawing does not show is not cut:** hidden layers and shapes were cut with the rest.
- **SVG paths and rectangles are drawn as they are:** the line after a close (`Z`) lost its first point, rounded rectangles were cut with sharp corners, and a size with a unit or a broken point silently left the shape out (now the file is refused).
- **Plotter arcs and circles are drawn:** `AA`, `AR` and `CI` were skipped, so the pen stayed behind and the next line ran from the wrong place; scaled, rotated or encoded plotter files are refused instead of cut at another size.
- **Post-processors number a program without breaking it:** old line numbers stayed beside the new ones, and `%`, `O` and `$` lines were numbered or rewritten.
- **The emergency stop reaches the machine of the server:** the red button and the entry of the menu only stopped the controller of this computer, so a job sent to the server went on running. They now also send the emergency stop of the machine on a thread of its own, while the job is not known to be over; a server that does not take it gets the plain stop, and the log says in the eight languages what arrived. Tried against a stand-in server only.
- **A stop that does not arrive is said every time:** the log says that the machine may still be moving, in the eight languages, each time a stop fails, and a stop pressed just before the program stops following the job is still sent.
- **No second job beside one that may still run:** after a failure the job is made again only when the server says the old one ended in failure or was cancelled, or answers that it does not have it. When it cannot be asked, or the answer is not understood, nothing is sent.
- **A running program is not changed under the controller:** opening or dropping a file, a recent file, applying the editor, Rewind and Clear replaced or reset the program while it ran or waited paused, with no stop sent to the controller. They are now refused with a line in the log.
- **A stop stops the queue:** a stop, an emergency stop or an alarm ends the wait between two runs, which started the next run all the same, and a stop on the last lines no longer counts as a program that finished. The wait no longer loads the program over a run started by hand, and Continue waits until the machine is free.
- **A restarted program keeps cutting when it was cutting:** the program that starts from a line now says `G0` or `G1` after its pause; before, a line that named only axes ran in whatever way of moving the controller was left in, which could be a rapid through the material.
- **Arcs are known as a way of moving:** `G2`, `G3`, probes and `G80` are now followed as the way of moving in force, and starting from a line, resuming and restarting are refused where the next line goes on in one of them without saying it: a straight cut or a rapid would have taken the place of the arc.
- **What cannot be written back refuses the start:** a feed by inverse time or per revolution (`G93`, `G95`) and a tool length offset from the table of the controller (`G43`) refuse starting from a line, resuming and restarting, with the line that set it, in the eight languages.
- **The feed and the length offset keep their units:** when the program changed units after giving an `F` or a `G43.1`, resuming and restarting wrote the number under the new units, 25.4 times wrong. Each is now written under the units it was given in. Simulator and host tests only.
- **A board file with an error is not cut:** when a drill file had at least one hole, every error of the reader was ignored and the drilling was made all the same, with holes missing or elsewhere; a Gerber layer with shapes did the same. Any error now refuses the file.
- **A drill file that does not say its numbers is refused:** with no coordinate format, zero suppression or units the positions rest on a guess and can be many times off. `pcb_allow_assumed_drill` in the motion file (off by default) drills them all the same and says so. The shared readers are taken at their tag v0.1.4, which tells these suppositions.
- **A plotter file with a number that cannot be read is not drawn from what is left:** the number was dropped and the ones after it were paired the wrong way round.
- **The buttons of the program panel fit it:** in a narrow panel the last button was cut off in the longer languages; they now go to a further row. The pictures of the window are new.
- **A line is read as the controller reads it:** a `;` inside a comment hid the words after it from the path, the keep-out boxes and the checks; a move behind a comment, with blanks inside or with axis words only was not seen as a move by the guard after a stop; a `$` line behind a comment was sent although the settings refuse it; a post-processor that strips comments dropped every word after a comment in parentheses. The warnings say when a line cannot be read, when the program pauses with the spindle turning and when `G93` or `G95` changes what `F` means. Host-tested only.
- **Safety text corrected: the server starts the spindle when a job sent to it goes on.** `server_restore_outputs` decides the coolant only. While the job waits before its first move, the log says in the eight languages that the machine goes back on its own to where it stopped and starts the spindle the program had on.

- **A project saved by another program is not written over:** the window keeps the mark of the project from the moment it opens or saves it, looks at it again after a question, and refuses to save, import or take when another program wrote the file meanwhile. It says so in the eight languages and offers to read it again, to save under another name or to close. 2 new tests.
- **What the tag v0.3.7 of EH3D-COMMON brings to the window:** the panel «Attachments» refuses the same writes and reads its list again, and `viewer.max_preview_mb` (16 by default) in the settings says how much text a whole preview keeps.

## [0.2.5] - Safer resume of a stopped program (not tried on a machine)

- **Going on after a failure is refused where it cannot be made right, and takes back the moves the controller may not have made:** a program that shifted the zero with `G92` (a reset of the controller takes the shift away), that has a canned cycle or a cutter compensation still on, or that last moved an axis with `G28`, `G30` or `G53` is not resumed, and neither is one whose lines that may have run set an offset with `G10`; the log says the line and why. The `resume_backoff` margin now counts lines that move, not comments or blank lines, and applies to a job on the server too. A tool length offset given in inches is given back in inches. A job on the server that finished, or one that would start again from the first line, is not sent again by itself. Tried against stand-ins only, never on a machine.

- **The panels of the machine state and of the jog adapt to their size:** in a low window the list of active G-codes was cut at the foot of the state panel; the panel now draws its rows smaller there, with the two speeds side by side and the codes after their titles. In a narrow window the buttons A+ and A- of the jog were cut; the pad now draws closer and smaller, and in a narrower panel Z and A go under X and Y. Two tests draw the panels with no screen at several sizes.

- **Escape answers no to the question before a project is written:** the question that the window asks before a write removes a signature (or replaces a branch it did not write) closes with Escape without writing, Enter does not write and no key starts the machine behind it; while something runs Escape stops it as before. The commands do not ask.

## [0.2.3] - Starting points for feeds and speeds from the shared materials, Marlin and Klipper output, chip load checks

- **`--feeds MATERIAL[,OPERATION[,DIAMETER[,CUTTER]]]` tells the starting point of a material of the shared database:** `src/sharedmat.rs` reads the machining database of `eh3d-materials` (EH3D-COMMON, the same one the other programs of the suite use) and gives, for a material (its identifier such as `wood/mdf`, its short name or its name in any of the eight languages), an operation (`contour`, `pocket`, `engrave` or `drill`) and a cutter of a diameter, the spindle speed, the feed, the plunge feed, the depth of a pass and the step over. Between two known diameters the point is a straight line between the two nearest ones and the line says so; outside the known diameters nothing is extrapolated, the answer is the warning of the database in the language and the exit code is 2. Every point carries the note that the seed of the database was never tried on a machine, in the eight languages. Nothing moves.
- **With no diameter, `--feeds` lists the points of the material, and `--materials FAMILY|all` lists the materials a router works:** `--feeds wood/mdf` (or with an operation, `--feeds wood/mdf,pocket`) prints every point of the material with its cutter, its diameter, its speed, its feed and whether it was tried on a machine; `--materials` prints the materials that have points for a router (all of them or one family) with their names in the language, the number of points each has and how many were tried on a machine (none of them yet). A family that does not exist is refused with the list of the families.
- **The chip load and the cutting speed come with every point:** the thickness of the chip of each tooth (the feed divided by the revolutions and by the teeth), its share of the diameter and the speed of the edge in metres a minute are worked out for each point whose teeth are known, and a line says when the chip is below 0.2 % of the diameter (the cutter rubs instead of cutting) or above 8 % (a small cutter may break); where the teeth are not known it says that the chip load is not worked out. The two limits are a rule of thumb for small cutters, never measured on a machine.
- **The material of the settings can be one of the shared database:** when the library of the operator has no material with the name in `material` (the file next to the settings, or the one built in), the name is looked for in the database by identifier, by short name and by its name in each language, and the check of a program is held to the lowest and the highest feed and speed of its points (the ranges the table gives where it gives them). A material of the library with the same name still wins, an unknown name still gives no range, and nothing is held to a range that does not span anything.
- **`--format marlin` and `--format klipper` join `grbl`, `full` and `generic`:** the profile of Marlin lists the G and M codes of its documentation for a machine that moves, probes and has work spaces (`M30` is not an end there: it deletes a file of the card, so a program that ends with it is told so), holds a line to the 96 characters of its buffer and asks for no end; the profile of Klipper lists what its base takes (millimetres only, so `G20` is read, no spindle and no coolant). A code a profile does not list is a reason to read the line, not a proof that the controller refuses it, and a file of your own can start from either (`base = marlin`).
- **The shared crates are built against EH3D-COMMON v0.3.0:** the two workflows that build the program (the checks and the binaries of a release) take the sibling at that tag, which carries the Marlin and Klipper controllers, the simulators, the fixed token of the client and the HTTP link of Klipper this program already uses, and the machining database the new tools read.
- **More tests, all from a fixed seed:** fifteen tests in `tests/shared.rs` draw from one seed (a generator on 64 bits, the same on every system) four hundred starting points and check that none leaves the points it comes from and that a diameter outside them is always a warning, that the same seed gives the same text in each of the eight languages and another seed another one, that every material is found by identifier, short name and each language, that every point of the database is judged for its chip load and the line agrees with the verdict, that the verdict only goes up as the chip gets thicker, that the library material of every database material holds its points, that the formats of Marlin and Klipper read a printer program as clean and a milling program as what it is, and that `--out` writes a new file and never over one that is there.
- **The READMEs and the register say what the program does today:** the eight READMEs describe the tools above, the row of machine control names Klipper and says that its HTTP link has only met a stand-in Moonraker, the tree of files lists `src/sharedmat.rs`, and the register of requirements has six more rows (PCNC-134 to PCNC-139, all with the test that names them; 139 in all, 130 implemented) with the count of tests (986).

- **The controllers and the simulated devices come from the shared controller crate:** the Marlin controller, the simulated GRBL, grblHAL and Marlin devices, the cable that spoils the bytes, the controller that goes wrong on purpose and the texts of the errors are those of `eh3d-controller` (EH3D-COMMON), and this program no longer carries a copy of any of them. What stays here is the detection of the dialect, the guard, the settings and the messages of the guard (`src/ctltext.rs`). The shared crates are pinned to the release of EH3D-COMMON that carries them, the tests that moved are run there, and the requirements that named them now name tests of this program.
- **Klipper, through Moonraker over HTTP, behind the guard:** `--klipper HOST[:PORT]` drives Klipper with the HTTP link of `eh3d-controller` (port 7125 when none is given; plain HTTP, one connection for each message, no TLS and none of the notifications a WebSocket would push). Only the local network is reached unless `klipper.allow_non_local` is on in the motion file; a name needs the switch too, and an unspecified, multicast or broadcast address is never taken, all refused before any connection. The motion file has the `klipper.*` keys with their ranges (the host, the port, the switch, the timeouts, the limits of an answer, the requests in flight, the longest a move waits); a key out of its range, an address that cannot be reached and a script that would be cut off before the controller gives up (`klipper.response_wait_ms` shorter than `klipper.busy_limit_s`) are named with their line in the eight languages and keep the default. The credential, `klipper.api_key`, is read from the file, sent only in the `X-Api-Key` header and never printed: not by `Debug`, not by a fault of a line, not by the text of the file the program writes, not by an error. `--sim klipper` and `--dialect-check klipper` try the same controller against the simulated Klipper (a machine that is not homed refuses the move, a silent link stops the machine under the guard, noisy cables from eight seeds), and the errors of Klipper and of its link (numbers 201 to 219) are told in the language of the window in the log. Only a stand-in Moonraker in the tests has answered it: nothing was tried on a real Klipper.

- **grblHAL and Marlin are driven like GRBL, behind the same guard:** `--grblhal PORT[@BAUD]` drives grblHAL (the controller of GRBL reported as its own family) and `--marlin PORT[@BAUD]` drives Marlin (250000 baud when the option names only the port) with the `MarlinController` of `eh3d-controller` in EH3D-COMMON: Marlin has no state report (the position comes from `M114`, the work offset of `G92` is followed by the program), no jog (a jog is `G91`, a relative move and `G90`, and the machine is put back in absolute mode whatever happened to the move), no hold that can be resumed (the hold is the quick stop `M410`, the safe side) and no numbers for its errors, so each kind of error (an unknown command, a line number out of step, a bad checksum, a failed homing or probe, a halted printer, a temperature error, anything else) has a number of its own from 101 that cannot be mistaken for a number of GRBL. A halted Marlin is an alarm and refuses everything until `M999`; a move that got no answer is stopped with `M410`; the longest travel is read from `M211`. Only one of `--grbl`, `--grblhal`, `--marlin` and `--klipper` can be given, and `--start` with any of them needs `--start-real`.
- **Simulated devices behind a cable that misbehaves, from a fixed seed:** `wire` of `eh3d-controller` (EH3D-COMMON) puts a simulated controller behind the line transport the controllers read and spoils the bytes by a schedule that a seed makes the same on every computer: the answers are cut into pieces of 1 to N bytes, lines of noise come between them, a bit of one byte of a line the program writes is flipped, and the device falls silent for a number of lines. `grblsim` is GRBL and grblHAL as devices (the greeting and the build report of each, the status with the pins and the accessories of grblHAL, the alarm that asks for homing at the start of grblHAL, `M6` taken by grblHAL and refused by GRBL, the lock after a move past the travel, a line made to fail by its number with the code the firmware gives) and `marlin` has the simulated Marlin (the keep-alive lines of a busy controller, numbered lines with a checksum and `Resend`, `M112`, `M999`). `--sim grbl|grblhal|marlin` drives one of them in the window or on the command line, with nothing real. The seed, the size of the pieces, the noise, the flipped bits and the numbering of Marlin are the `wire_` keys and `marlin_numbering` of the motion file.
- **The errors of the dialects are told in the eight languages:** `dialtext` of `eh3d-controller` has the errors and the alarms that grblHAL adds to the ones of GRBL and the kinds of error of Marlin, in English, Spanish, German, French, Italian, Japanese, Chinese and Portuguese of Portugal, and `explain` looks in the table of the family first, then in the table of GRBL for the families that speak it, and keeps the text of the controller when no table has the number.
- **`--dialect-check grbl|grblhal|marlin|klipper` tries a dialect against its simulator:** a battery of steps (status, a move, a jog, the homing, a refusal by number told in all eight languages, a silent controller under the guard that must be stopped and then refuse what moves, and the same steps on noisy cables from eight seeds), one line a step and a verdict in the language; it ends with exit code 0 when every step passed and 2 when one did not (the check was not passed).
- **Boards from Gerber and Excellon files:** `--import` reads a Gerber layer or an Excellon drill file with the readers of EH3D-CORE-LIBS (the same ones the other programs of the suite use; the repository now depends on it by path, the CI pins it with the other sibling) and prints the program that cuts it (`src/pcb.rs`): the isolation of a copper layer made by the CAM of the library (as many passes as `pcb_passes`, the grid and its size checked before it is made), the profile of an outline layer (the strokes are joined into loops, the biggest loop is cut outside the board and the others inside, the cut-outs first, in passes of depth, and an outline that is not closed is cut along the line and says so), and the holes and slots of a drill file (the smaller drill first, a pause with the diameter in its comment or `T1 M6`, the nearest hole next, pecks). The layer is what the file says (the attribute of a Gerber X2 file, then the end of the name); `--layer isolation|profile|drill` says it otherwise, the layers of the bottom are mirrored (`pcb_mirror_bottom`, or `--mirror`), the zero of the file is kept so that the layers stay aligned (`pcb_zero_origin` moves it), and a file over the limits of size, shapes or cells, a layer that is not cut (the mask, the legend) and a setting the CAM cannot use are failures told in the eight languages.
- **The import panel takes boards:** the panel chooses the layer (what the file says, isolation, profile or drill), mirrors it, and says how it was cut and how many cuts, holes and drill sizes it has; the panel and the command line share the same code.

- **`--start` no longer moves a real machine as the window opens:** with a real controller (`--grbl`) it is refused unless `--start-real` is also given, and `--start-real` alone is an error.

Tried against the simulator only.
- **The answer of the server has a limit and the ids that go into a request are checked:** the reply to a request is read up to 1 MiB and a longer one is an error (the follow-up thread asks every 300 ms, so a reply that never ends could grow without bound); the machine of the settings and the id of a job that the server gives are used in a path only when they are letters, digits, `_` or `-` (up to 64), so an id with `/` or a space cannot change the request, and a machine written otherwise is treated as missing. Tested with refused ids.
- **The refusal for a program that leaves the travel no longer depends on the summary window:** with the confirmation of the start turned off, in the queue, when sending to the server and in a `--start` run, a program that leaves the machine's travel is refused (and the reason goes to the log) as long as `reject_out_of_travel` is on, which it is by default.
- **The README and the manifest say what the program really does:** by default it drives a simulated machine, with `--grbl` it opens a serial port, and with a server address it opens a network connection and sends the token over HTTP.
- **A program can no longer change the controller's own settings by accident:** a line that starts with `$` (such as `$130=9999`, `$20=0`, `$X` or `$RST=*`) stops the program at that line without sending it and says so in the log, unless the settings file has `program_system_commands = yes`; the lines the operator types are not affected. Tested with and without the setting.

## [0.0.6] - Send the program to the server, pause, resume and go on after a failure

- **The program sent to the EH3D server:** the settings (section Server of the window, or `server_address`, `server_token` and `server_machine` in the settings file, the token hidden in the window) say where the server is, who this program is on it and which machine it works for. **Program > Send to the server** (and a button beside Start) sends the text of the program as a G-code job and starts it; the window follows it on a thread of its own (the state, the percentage and the line reached in the top bar, the program panel and the log), Start, Pause and Stop reach the job on the server, a stop is a stop of the machine there, and closing the window leaves the job running. Tested against a stand-in server (the request, the following, the orders, a refusal, the job made again from a line); the server's own tests send the same requests to its simulator.
- **Going on after a failure, through the server:** while a job on the server runs the file next to the settings keeps the id of the job and the line the server reached; at the next start the window offers to go on, follows the job if the server still has it, or sends the program again from the line the failed job reached. The server gives the codes in force back (units, distance mode, plane, coordinate system, feed) and waits for the operator before the first move; the spindle and the coolant start again only with `server_restore_outputs = yes` (off by default).
- **Words:** the Server section of the settings, its three fields and the menu entry in all 37 languages (they live in the texts of EH3D-COMMON). 8 tests more (the settings file, the file the window goes on from, the requests and the following of a job).
