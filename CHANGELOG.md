# Changelog

All notable changes to this project are documented here.

## [Unreleased]

- **The slot of each tool in the tool changer comes from a table in a file:** `phoenix-cnc-atc.txt` next to the settings file (`examples/atc.txt` is a model) has one `tool = NUMBER | pos=X,Y` line for each tool of the rack, and the steps, the G-code and the time of a change go to those slots; a tool that is not in the table keeps the rack and the pitch of the `atc` line, and with no file nothing changes. A line that cannot be used is left out and named with its number and the reason in the eight languages: not in the form of the line, a tool that is not a whole number from 1 to 255, a position that is missing, not two numbers or beyond 100000 mm, a tool that has a slot already (the first line stays), a slot less than 1 mm from the slot of another tool, more than 64 tools, a file bigger than 16 KiB (not read) or one that cannot be read. `phoenix-cnc --report` and the Statistics window list the size of the table, those lines and every tool a program takes that the table does not have (once each); the window looks the file up again whenever the settings are applied, and **Defaults of this section** keeps the table. Nothing is written. The rules are `RackTable` in `src/atc.rs`, tested for the lines, the limits, the file, the example and the report.
- **The settings window has a Tool changer section and a Materials section:** the list of the settings window grows from three to five sections of program tools. **Tool changer** has the tick that turns the simulation on, a number for the safe height, the three coordinates of the slot of tool 1, the step to the next slot, the output pin and the wait of the lock and the output pin and the seconds of the blow (each number only inside the range the `atc` line accepts, shown as its tooltip; the line now also refuses a step beyond 100000 mm, as it already did for the rack), the table of slots read from its file with the lines that were left out, and a button that writes the example table next to the settings and never over a file that is there. **Materials** has the choice of the material (also still in the checks section), its two ranges, the place of the library file and a button that writes the example library without writing over a file. **Defaults of this section** puts the tool changer back to off (the table of slots is a file of its own and stays) or clears the material, and the tool changer is no longer reset with the queue. `--window settings-atc` and `--window settings-materials` open them for the pictures, and the texts are in the eight languages.
- **An editor for the table of materials inside the settings window:** the Materials section has **Edit the library...**, which lists the materials in use with a name, a feed range and a speed range (each one can be switched off) and a button to remove it, a button to add a material and **Save the library**. Every row is checked as it is written (a name the file could not keep, no range, a range that does not go from 0 or more up to something bigger within 1000000, a name that repeats an earlier one, more than 64 materials) and the problem is said with its row in the eight languages; Save is off while there is one. The library is written to `phoenix-cnc-materials.txt` next to the settings file only when it would read back as it is, and when the file is there already the window asks **Replace** or **Cancel** before it writes. The list and the ranges of the material in use are read again after a save or after the example file is written. The rules are `check_library`, `to_text`, `save` and `create_sample` in `src/materials.rs` (a file is never written over unless the caller says so) and the buttons are in `src/gui/prefs.rs`, tested through the window with real files.
- **Bookmarks kept in a file between sessions, with keys:** **Program > Bookmarks and start from a line...** has **Save the bookmarks next to the program**, which writes `part.nc.marks` beside `part.nc` (the bookmarked lines counted from 1 and the SHA-256 fingerprint of the program, up to 200 bookmarks, a file of up to 16 KiB), and **Load the saved bookmarks**, which adds them to the list. When the file is there already the window asks **Replace** or **Cancel** first (`bookmarks_confirm_replace = no` turns the question off), and a file that has these very bookmarks is left alone. The file is read again whenever the program is opened (`bookmarks_load`, on by default; both switches have a box in the Queue, macros and log section of the settings and are in the example of the settings file): a file written for another version of the program, because the program was edited since, is left out and the log says so, so a bookmark never lands on a line it was not made for; marks past the end of the program are dropped. **Ctrl+B** bookmarks the selected line and **F2** and **Ctrl+F2** go to the next and the previous bookmark; the keys are in the list of keys and written beside the three entries of the Program menu (the keys do nothing while a window is open). The rules are `Bookmarks::save`, `load` and `parse` in `src/bookmarks.rs` (tested for the text, the fingerprint, the limits and that a file is never written over unless asked) and the words are in the eight languages.

## [0.1.6] - Editor saving in place, a start from a bookmarked line, fixed views, materials and a tool changer in simulation, and --profile on the command line

- **The editor saves straight over the file, asking in line:** **Apply and save** in the editor window no longer opens the Save window: it shows the question "the file already exists, replace it?" inside the editor, with **Replace** and **Cancel**, and only Replace applies the text and writes it over the file the program came from. The question is tied to the text it was asked about: if the text changes after it, the question goes away and must be asked again; nothing is written while a program runs or when the program has no file. **Apply and save as...** still goes through the Save window. The question and its rules are in `src/editor.rs` and the write is tested through the window with a real file.
- **`--profile NAME` starts with a machine profile:** `phoenix-cnc --profile NAME` takes the values of a machine profile saved in the settings (the travel of the three axes, the spindle speed and its limit, the feeds and the probe values) before the window opens, so one program can start for each of several machines; it also works with `--report`, which uses that machine's limits. A name that is not saved leaves the settings as they are: the window says so in its log (in the eight languages) and `--report` refuses with exit code 2. A name with nothing in it is refused. It is in `--help` and tested in `src/cli.rs` and in the window.
- **Transform asks where the tool stands before the program:** when the first move of the program says only X or only Y (so the other coordinate depends on where the tool is before the program starts), the Transform window shows a warning with the line and two fields for the position of the tool before the program, with 0, 0 as the default. The transformation takes the coordinate that move leaves out from that position and writes it on the line whenever the change moves it (a shift in that axis, a turn, a scale or a mirror), so the new program ends up on the same path as the old one moved; before, that coordinate was left unwritten and the tool kept the old one. A change that does not move the missing coordinate leaves the line as written, and a start on its own is no change. The position is `Transform::start` and `needs_start` in `src/transform.rs`, tested for the lines that need it, for the written coordinate with and without a start and for a turn.
- **Bookmarks on the lines of the program and starting from a line:** a click on a line of the program panel selects it and a double click bookmarks it (the bookmarked line shows a star after its number); **Program > Bookmark the selected line**, **Next bookmark** and **Previous bookmark** do the same from the menu, and **Program > Bookmarks and start from a line...** (also `--window bookmarks`) lists the bookmarks (a click on the number shows the line, **Remove** drops one, **Clear the bookmarks** drops all, up to 200, kept for the program that is loaded) and starts the program from one of them or from the selected line. Before anything is prepared the window reads the lines before the start and says what the program had in force there: inches, a plane other than XY, the work coordinates, a tool length offset, the last tool asked for (no tool change is made), the spindle and its speed, the coolant, a shifted zero, and a cutting move before any feed; a start with relative distances (`G91`), a canned cycle or a cutter compensation still on is refused with the reason. **Prepare the start** needs a tick that says the tool, the spindle and the zero were checked (`startline_confirm`, on by default, has a box in the Queue, macros and log section of the settings), then brings the controller back to that state the way a program left in the middle is resumed (to the safe height, the spindle with its wait, over the point the program had) and leaves the program paused at the line, so the machine moves only when Resume is pressed; a program that runs, here or on the server, is never touched. The words are in the eight languages and the rules are `src/bookmarks.rs` and `src/startline.rs`, tested without a window for the order and the round trip of the bookmarks, each state noted, each refusal and the preparation of the start.
- **Fixed views of the viewer: top, front, side and isometric:** the **View** menu (and **Ctrl+1**, **Ctrl+2**, **Ctrl+3** and **Ctrl+4**, listed in the list of keys) puts the path in one of four views: **Top view** is the plan from above (the drag and the zoom of the plan are undone), **Front view** looks along Y with X across the screen and **Side view** looks along X with Y across the screen, both level with the table and at zoom 1, and **Isometric view** is the usual one the window starts in; dragging from a level view tilts it again. The command line takes the same words, `--view top|front|side|iso` besides `plan` and `3d`, so `--shot` can take a picture of each. The angles are `Orbit::preset` in `src/view.rs`, tested through the projection (in the front view a change of Y moves nothing on the screen, in the side view a change of X moves nothing, the middle of the table stays in the middle) and the words and keys in the eight languages.
- **A library of materials with suggested feeds and speeds, used by the checker:** the checks section of the settings has a **Material** list (`material = NAME` in the settings file, none by default); with a material chosen, the checker holds the program to the range of cutting feed and of spindle speed suggested for it and says, with the line and in the eight languages, when a move in X or Y runs below or above the feed range (a plunge in Z alone and rapid moves are not held to it, and inches are converted), or when an `S` is below or above the speed range (`S0` is not). The ranges are not in the code: `examples/materials.txt` (nine materials, built into the program) is the library while there is no file of the operator, and `phoenix-cnc-materials.txt` next to the settings file replaces it, one `material = NAME | feed=LOW,HIGH | rpm=LOW,HIGH` line per material (up to 64, either range may be left out, a line that is not valid is dropped, a file bigger than 64 KiB is not read). The window looks the library up again whenever the settings are applied and `phoenix-cnc --report` uses the material of the settings. The ranges only warn. The rules are `src/materials.rs` and the four new findings of `src/lint.rs`, tested for the ranges, the plunges, the inches, the library file and the settings.
- **A tool changer with a lock and a blow, in simulation:** a line `atc = on | safe=5 | rack=0,0,-5 | pitch=20,0 | lock=3,0.5 | blow=4,1` in the settings file (off unless it says `on`; the example shows it as a comment) describes a changer with a rack (the X, Y and Z of the slot of tool 1 and the step to the next slot), the safe height, the output pin that clamps the tool and the seconds the clamp needs, and the output pin of the air and the seconds it blows. For every change in a program (`T` then `M6`) the program works out the steps the machine would make: stop the spindle, go to the safe height, put the old tool in its slot and release the lock, blow the empty spindle clean, take the new tool from its slot and engage the lock, and go up again; the lines of G-code that do it (`M5`, `G0`, `M65 P` / `M64 P` for the lock and the air, `G4` for the waits) and the time of the moves at the rapid speed plus the waits. With the changer on, `phoenix-cnc --report` and the Statistics window list every change (the line, the tools, the seconds and the pins), and the estimate of the time (the time left, the queue, the summary, the statistics and the work report) adds the time of a typical change in place of `tool_change_time`. Nothing is sent to a machine: this is the simulation, and the lines are for when a controller takes them. The rules are `src/atc.rs`, tested for the line, the slots, the order of lock, blow and lock, the G-code, the time and the list, and the words are in the eight languages.

## [0.1.5] - A program editor, transformations of a program, machine profiles, arcs and tool changes in the summary and options for the pictures of the viewer

- **The CI and the release build take the shared library at its newest release:** the pin of the shared library is raised to the release that the program now needs, so the binaries of a release build again.
- **The summary before the start counts the arcs and the tool changes:** the check made before a program runs measured only the straight moves and warned that arcs were left out; it now measures an arc along its curve (a helix with its rise) in the cutting distance and the time, adds the tool-change time of the settings (`tool_change_time`) once for every change of tool, and says in its facts how many arcs and how many changes there are (in the eight languages of the program tools). The warning about arcs is gone, since they are counted; the one about cuts before any feed stays. The numbers are those of the time shown while a program runs and of the queue, and `src/plan.rs` tests them with a half circle and a change.
- **`--color MODE` and `--select LINE` on the command line for the pictures:** `--color` starts the window with the path coloured by `state`, `kind`, `progress`, `tool` or `feed` (capitals do not matter; another word is refused and the message lists the five), and `--select` selects the move of a line of the program, counted from 1 as the program panel does, so that its line is shown and it is drawn thick; a line with no move selects nothing, and `--select` without a G-code file is refused. Both go with `--shot` to take the pictures of the viewer without a click, and they are in `--help`; the words and the line of a move are tested in `src/cli.rs` and `src/viewer.rs`.
- **Zoom to the selection also works in 3D:** the button under the title of the path, which only worked in the plan, now also magnifies the 3D view: the middle of the selected move goes to the middle of the view and the zoom is raised until the move takes 70% of the width or of the height (up to the limit of the zoom), keeping the turn and the tilt the view has. The wheel and the turn keep the point in the middle, and **Reset view** or a double click brings the usual view back. The numbers are `Orbit::zoom_to_line` in `src/view.rs`, tested for the middle, the size and the limits at several turns.
- **An editor for the program with line numbers, find and replace, go to a line and the notes of the check:** the editor window (Ctrl+E) now shows the numbers of the lines in a margin, in the colour of the worst thing the check says about each line, and has **find and replace** (with or without capitals, Enter for the next match, replace one or all, the count and the line of the match said), **go to a line** (the line is selected and scrolled to), the **notes of the check for the text as it is being written** (the same checks as the Check window, made again when the text changes, with a button on each note that goes to its line) and the number of lines. **Apply** puts the text in the program and is off while a program runs; **Apply and save** and **Apply and save as...** go through the Save window, which asks before it replaces a file that is there. The rules are in `src/editor.rs` and are tested without a window; the texts are in the eight languages of the program tools.
- **Machine profiles in the settings:** the General section of the settings window now lists the profiles saved and lets the operator save the values in use under a name (the travel of the three axes, the spindle speed and its warning limit, the jog feed, the rapid speed and the feed warning limit, and the five values of the probe) and take them again with one click; Ok keeps the choice and the travel reaches the machine, and Cancel drops it. The settings file keeps one `profile = NAME | tx=0,500 | ty=0,300 | tz=-100,50 | spindle=10000 | ...` line for each profile (up to 16, names of up to 40 characters; a name cannot carry a line break or the signs of the file, a value outside its range keeps its default and a repeated name keeps the first) and `profile_active = NAME` for the one in use (it is dropped if no profile has that name). A new profile name that exists already replaces that profile. The rules are in `src/profiles.rs` and are tested without a window; the texts are in the eight languages of the program tools.
- **Transform the program: shift, turn, scale and mirror, with undo:** **Program > Transform the program...** (also `--window transform`) changes the program that is loaded: a shift in X, Y and Z, a turn in degrees about a point, a scale above 0 and a mirror of X and Y, done in that order (mirror, scale and turn about the point, then the shift), and **Program > Undo the transformation** brings the program back while it is still the one the change made. The lines are rewritten in place so the words that do not change, the comments and the spacing stay as they were; a turn writes both coordinates of a line that had one; the centres of the arcs are turned, scaled and mirrored with the path and one mirror swaps `G2` and `G3` (an arc that takes its code from an earlier line gets it written). A program the change could make wrong is refused with the line and the reason in the language of the window: relative distances, a plane other than XY, canned cycles and probing moves, the codes that take machine positions or shift the zero, absolute arc centres, or a scale that is not above 0. A program that runs, here or on the server, is never changed. The rules are `src/transform.rs` and are tested without a window, among them that the path of the new program is the old path transformed and that a turn and its opposite bring a program back.

## [0.1.4] - A settings window for the program tools, a path viewer with colours, a work report in one page, arcs and tool changes in the time and Tab completion

- **Tab finishes the code in the command box:** while the box at the bottom of the window has the keyboard, Tab finishes the G, M or `$` code being typed (`G38` gives `G38.`, `M30` gives `M30 `, `$J` gives `$J=`) or, when several fit, writes the start they share and lists them beside the box (`G5` lists `G53` to `G59`). It works on the last word of the line, ignores capitals and small letters, puts the cursor at the end and sends nothing (the line still goes with Enter); the list of codes and the rules are in `src/complete.rs`.
- **The path in the plan and in 3D can be coloured, filtered by tool and clicked:** a row under the title of the path chooses how it is coloured (done or to do, as before; the type of move: rapid, cutting, plunge and arc; the progress of the program from blue to red along the length travelled; the tool; or the feed rate from the slowest to the fastest), has a box for each tool of the program to hide or show its moves (the last tool shown cannot be hidden, and a program change drops a hidden tool that is gone), and **Zoom to the selection** for the plan (the view is put on the move, magnified up to the limit of the zoom). A click on a move (within 7 pixels) selects the nearest one that is shown, draws it thick, shows its line in the program panel and says the line, its code, the kind of move, its length, its feed and its tool; a click on nothing clears the selection. The plan keeps its drag, wheel and double click, and the 3D view its turn. The numbers (`src/viewer.rs`) are tested without a window.
- **A work report as one page of HTML:** **File > Export the work report...** (enabled when a program is loaded) and `phoenix-cnc --report FILE.NC --html REPORT.html` write one page that holds everything in it, with no script, no link and no separate picture: the statistics and the time of the program (with the tool changes and the curve of the arcs), a table of the tools, what looks wrong with its line and level, the path seen from above (cuts, dashed rapids and a ring on the first move of every line that has a warning) and the height map as a grid of colours with its range when one was measured. The page has its own light and dark colours, follows the language of the program in the eight languages (HTML-escaped throughout), draws at most 40000 moves of the path, and is never written over a file that is there.
- **Every window can be opened by name for a picture, and the Macros window lists the macros:** `--window` takes `macros` (a new **Macros** window with the name, the note and the first lines of each macro of `phoenix-cnc-macros.txt` and a button to run it, which asks first when the macro has to; with no file it says where the file is), `probe` and `probe-grid` (the questions before the machine moves) and `resume` (the question about a program left in the middle), besides the windows it opened before; the names are one list that `--help` prints and a test opens each one.
- **The settings window has three sections for the program tools:** **Checks** (the first checker `lint` and its floor for rapid moves, highest feed and highest spindle speed, the second checker `progcheck`, and the margin and the refusal of the keep-out boxes), **Probe and height map** (`probe_feed`, `probe_depth`, `probe_retract`, `probe_plate`, `probe_clearance`, `probe_grid`, `heightmap_segment` and the limits of the jog `jog_soft_limits`) and **Queue, macros and log** (`queue_repeat_max`, `queue_confirm_between`, `queue_pause`, `queue_remember`, `sim_speed`, `log_max_entries`, `macros_confirm`, `macros_max_lines` and `tool_change_time`). Every number is offered only inside the range the settings file accepts (`src/ranges.rs`; a test checks both ends of every range against the file reader, and the range is the tooltip of the field), **Defaults of this section** puts one section back, the texts exist in the eight languages, Ok saves a copy of all the settings so the keep-out boxes, the server and the recent files are kept, and `--window settings-checks`, `settings-probe` and `settings-queue` open each section for the pictures.
- **The time left counts the tool changes and the curve of the arcs:** the estimate of the time (the time left of the program panel, the queue, the statistics and `--report`) adds `tool_change_time` seconds for every `T` then `M6` that takes a different tool, before the move of its line (and the ones after the last move at the end), and measures an arc by its curve, not by its chord: `G2` and `G3` with the centre (`I`, `J`, `K`, in the plane of `G17`, `G18` or `G19`, relative or absolute with `G91.1` and `G90.1`) or with the radius `R` (a positive one is the short way, a negative one the long way), with the rise of a helix and the inches of `G20`. An arc with no centre and no radius still counts by its chord. The time left from a line also counts the change that comes with that line as still to do. The summary before a start keeps its own measure.

## [0.1.3] - Program checks, keep-out boxes, a simulated path, statistics and a queue with repeats, macros, a Z probe and a height map

- **The README says what the program tools do, how `--report` is used and which files the program writes:** the eight READMEs describe the Check, Keep-out boxes and Statistics windows, the repeats, the wait and the kept queue, the Macros menu, the height map and log files, the values of these tools in the settings file, `--report FILE` with its exit codes, `--version` and `--help`; the security paragraph names the files the program reads and writes (only where the operator says, the log never over a file, a queue that comes back never starts by itself); the tree of the files and the picture list the new ones; and the number of tests is the real one (344).
- **`--version` and `--help` answer without opening the window:** `phoenix-cnc --version` (or `-V`) prints the name and the version, and `phoenix-cnc --help` (or `-h`) lists every option the command line reads, including `--report` and the windows `--window` can open; both leave with code 0 and win over the other options. Before, `--version` was an unknown option. Tested for the options and that the help names each option and each window.
- **The height map can be saved to a file and loaded from one:** **Machine > Save the height map...** (enabled when there is a map) and **Machine > Load a height map...** use the same file windows as the programs, with their own types (`.map`, `.txt`) and names, and without the picture, the recent programs and the queue of the Open window. A file that exists is never written over without the operator saying yes (the same question as for a program), and a file that is not a map, is cut, has a height that is not a number or is bigger than 8 MiB changes nothing and the log says why. A loaded map is the map of the session, ready to correct the program. Tested by writing and reading back, and with four kinds of bad file.
- **The log of the session can be exported:** **File > Export the session log...** writes what the log has said (the lines sent, the answers, the warnings and the errors, each with the time since the window opened) as text, CSV or JSON by the extension, up to `log_max_entries` entries; a file that exists is never written over, the log says so and nothing is lost. The cell of a CSV that a spreadsheet would take for a formula is defused. Tested for the three formats, the refusal over a file, the kinds guessed from the lines and that the lines the session drops are not taken twice.
- **A Macros menu runs the macros of a file, asking first:** the menu lists the macros of `phoenix-cnc-macros.txt` (next to the settings file; the format is `[name]`, optional `info = ...` and `confirm = yes|no`, then the lines of G-code) with their `info` as the hint, shows the problems of the file (a bad name, a `$` line, a name twice, too long) and, when there are no macros, where the file is. Every macro asks before it runs (`macros_confirm = yes`, the default), and one that moves an axis or that the checker has a warning for asks even when that is off; the question shows the lines and the warnings. The lines go out like typed ones, in order, and the macro stops at the first one the controller does not take and says which; it is refused while a program runs or the controller is busy. Tested for the file, when it asks, the lines sent, the refusal while running and the language.
- **The queue of the window repeats programs, asks or waits between runs, shows its time and is kept between runs:** a program that waits in the queue has a box with the number of runs (up to `queue_repeat_max`) and the running one shows its run ("run 2 of 5"); between two runs of the same program the window asks the operator to place the work and confirm (`queue_confirm_between = yes`, the default), or waits `queue_pause` seconds with a Cancel button, or goes on at once when both are off, and the program is read from its file again each time. Between two different programs the summary stays the confirmation, as before. A line under the list says how many runs are left and how long they take, from the estimates that are kept. The programs still to run are written to a small checked file next to the settings while the window works (`queue_remember = yes`, the default) and come back at the next start waiting, with the runs they had left and a line in the log, but nothing starts until the operator presses Go on with the queue; the file is taken away when nothing is left. A queue that was left before it started also shows that button now. Also fixed: a window that opens another one while it closes (the end of a run asks for the summary of the next program) no longer has the new one closed by the old. Tested with and without the confirmation and the wait, the cancel, the skip during a wait, the time of the queue and the file.
- **Program > Statistics and simulation... plays the path on paper with the cursor on the line:** the window shows the statistics (distances cut and rapid, tool changes, the time with the tool changes added) and a slider over the time of the path; the line the tool is at is marked in the program panel (which scrolls to it), the part of the path before it is drawn as done and the tool of the simulation is drawn on the path in the plan and in the 3D view. A line number to jump to, a Play button that runs at `sim_speed` times real time (10 by default; the speed can be changed in the window and is kept in the settings file) and the time, the total and the time left are shown. Closing the window, or a key that closes it, takes the simulation away. Tested for the cursor, the tool, the play step, the language and the closing.
- **The program panel shows the time left:** under the line number it says the time left from the line the program has reached and the whole time of the path (the estimate of the summary, without the tool changes). The path is measured once for as long as it and the speeds stay the same, and each program of the queue only when its file changes. Tested for the value at the start, in the middle and at the end, and that the path is measured once.
- **Program > Keep-out boxes... edits the places the tool must not go, and a program that enters one is not started:** the window lists the boxes of the settings (a name and the two corners in mm of the machine), adds one (the same name replaces the box, a number may use a comma, a box with no volume or a name with odd characters is refused with the reason, up to 64 boxes) and takes one out, and writes the `keepout` lines to the settings file with the other values. With `keepout_reject = yes`, which is the default, the summary window, the start without the summary, the queue and the send to the server refuse a program with a move that enters a box (each box grown by `keepout_margin`) and say the first line and the box; `keepout_reject = no` only says it in the Check window. `--window keepout` opens the editor for a picture. Tested for adding, replacing, saving, taking out, the limit and the refusal with and without it.
- **Program > Check the program... lists everything that looks wrong, line by line:** one window with what the summary check, the second checker, the keep-out boxes and the travel find in the program that is loaded, coloured by how serious it is (a danger, a warning, a note) and counted ("N to read, M notes"); the number beside each finding shows that line in the program panel, which scrolls to it and marks it. The window is made again when the program changes, it is in the eight languages of the interface and `--window check` opens it for a picture. `--report` and the window read the same list. Tested for the lines and levels of the findings, the language and the boxes of the settings.
- **A program of the queue has a number of runs, and the queue can be kept in a checked file:** each program that waits can be set to run up to `queue_repeat_max` times (the loaded one counts its run, and one that is unstarted goes on from the same run), and the programs still to run are written, with the runs each has left, to a small text whose last line is a check of the rest: a text that was cut, changed by hand, written by another program, with a line that is not an item or with more than 256 programs is not taken back. A restored queue has every program waiting with `active` off, so nothing starts by itself, and a program whose file is gone is left out. The file is written to a side file and renamed, and taken away when nothing is left to run. Tested for the runs, the check and each way of breaking it.

- Repository scaffolding: the README in eight languages with the project status table, the Architecture and Repository Structure pictures drawn from `docs/architecture.json` and `docs/structure.json`, the CI workflow, the issue and pull-request templates, the code of conduct, the contributing guide, the security policy, the support page and the repository checks in `tools/`.
- The manifest says what the repository is today: a library with no tests of its own, no window and no machine control.
- The view of a job (the scene, the themes and the words of the interface) moved to `eh3d-view` of EH3D-COMMON, where every program of the suite can use it; this crate uses it from there.
- `run` scripts, and `build` and `test` scripts that wait for a key unless `NOPAUSE` is set.

## [0.0.1] - The scene, the themes and the words of the interface

- **The scene of a job on the table:** holes with their drill sizes, routing paths, the progress of the work, a drilling job and a routing job in one scene, the plan view and the isometric view of the machine fitted to the size of the table, and a check that tells what does not fit on the table before a job starts.
- **Themes:** Forge (the default), Neon Arcade, Glass Pro, the classic Windows grey and a theme that follows the colours of Windows (light or dark and the accent colour); a user can write their own in a text file. Every theme is checked for readable contrast.
- **The words of the interface** in English, Spanish, Italian, German, French, Portuguese, Chinese and Japanese.
